# AI Gateway

[English](README.md) · **Русский**

Самостоятельно размещаемая AI API-платформа, совместимая с OpenAI, под вашим
собственным брендом: API-ключи, учёт расхода и биллинг, веб-консоль для
пользователей и администраторов и три источника ответов — автоматизация
веб-чатов, импорт браузерной сессии или любой внешний OpenAI-совместимый API,
плюс локальные модели через Ollama (по желанию).

```
клиенты (OpenAI SDK, curl, opencode, aider, ...)
        │  https://ваш-домен/v1/chat/completions
        ▼
   ┌──────────┐     ┌────────────┐
   │  Caddy   │────▶│  api       │── PostgreSQL (пользователи, ключи, расход)
   │ (HTTPS)  │     │  FastAPI + │── Ollama        (локальные модели)
   └──────────┘     │  веб-UI    │── внешний API   (режим 3)
                    └─────┬──────┘
                          ▼
                    ┌────────────┐
                    │  cluster   │  экземпляры Chrome на виртуальном экране,
                    │            │  управление через CDP (режимы 1 и 2), VNC
                    └────────────┘
```

## Возможности

- **OpenAI-совместимый API**: `/v1/chat/completions` (стриминг, tools, vision,
  reasoning effort), `/v1/models`, `/v1/images/generations`, `/v1/images/edits`.
- **Свои названия**: имя платформы, имя ассистента и публичные id моделей
  задаются при установке; настоящие имена upstream-моделей клиенты не видят.
- **Аккаунты и ключи**: регистрация (опционально), вход через Google / Telegram,
  лимиты на ключ (в минуту и в месяц), история расхода, реферальная программа.
- **Биллинг** по реальным токенам — или бесплатный режим без балансов.
- **Админ-консоль**: модели и цены, пользователи, мониторинг и ошибки, настройки,
  экземпляры Chrome со встроенным VNC-просмотрщиком.
- **Надёжность веб-чатов**: проверка сессии, распознавание квот и капчи с паузами,
  переключение между каналами, контроль памяти, самовосстановление.
- **Языки интерфейса**: узбекский, русский (частично).

## Три режима

| Режим | Откуда ответы | Что нужно |
|---|---|---|
| **1. Автоматизация веб-чатов** | Экземпляры Chrome на сервере открывают веб-чаты провайдеров (Gemini, Qwen, DeepSeek, ChatGPT, ...). Вы один раз входите в аккаунты через встроенный VNC. | Сервер (~1 ГБ RAM на канал), свои аккаунты у провайдеров |
| **2. Импорт сессии** | Тот же кластер Chrome, но вместо входа через VNC вы импортируете свою сессию: cookies из браузера (JSON или `cookies.txt`) или JWT/сессионный токен из `localStorage`. | Экспорт cookies / токена из вашего браузера |
| **3. Внешний API** | Любой OpenAI-совместимый upstream (OpenAI, OpenRouter, свой vLLM, ...). Вы перепродаёте его под своими названиями и ценами. | Base URL и API-ключ upstream |

Любой режим можно дополнить **локальными моделями через Ollama** (в Docker на
том же сервере, с NVIDIA GPU или без, либо уже работающий у вас Ollama).

> **Условия использования.** Автоматизация потребительских чат-сайтов (режимы 1
> и 2) может нарушать правила провайдеров и привести к ограничению аккаунтов.
> Используйте только свои аккаунты, держите нагрузку низкой и проверяйте правила
> каждого сервиса. Проект не обходит капчу и защиту от ботов: если провайдер её
> показывает, оператор решает её вручную через VNC. Для продакшена лучше режим 3
> с официальными API.

## Требования

- Linux-сервер (рекомендуется x86_64; на arm64 кластер использует Chromium)
- Docker 24+ с плагином Compose v2 (`docker compose version`)
- RAM: ~1,5 ГБ на базовый стек + ~0,6–1 ГБ на каждый канал Chrome + память для
  моделей Ollama
- Для автоматического HTTPS: домен, указывающий на сервер, свободные порты 80/443

## Установка

```bash
git clone https://github.com/Inforteuz/ai-gateway.git
cd ai-gateway
./install.sh
```

Установщик спросит:

1. имя платформы и ассистента, язык интерфейса по умолчанию;
2. как открывать сайт: публичный домен с автоматическим HTTPS (Caddy), за вашим
   reverse proxy (локальный порт) или только локальный тест;
3. режим (1, 2 или 3) и для каждого канала / upstream-модели — публичный id,
   отображаемое имя и цены;
4. локальные модели через Ollama (опционально);
5. аккаунт администратора, открыта ли регистрация, бесплатный режим.

Затем он генерирует все секреты, пишет `.env` (права 600), собирает образы,
запускает стек, применяет миграции БД, создаёт администратора и модели.
`./install.sh` можно запускать повторно для перенастройки — секреты сохраняются.

### После установки

- **Режим 1** — откройте админ-панель → **VNC** и войдите в аккаунт в каждом окне
  Chrome. Логины хранятся в Docker-томе `cluster-data` и переживают перезапуски.
- **Режим 2** — импортируйте сессию для каждого экземпляра:

  ```bash
  ./manage.sh import-session 0 gemini cookies-google.json
  ./manage.sh import-session 1 deepseek --token userToken='{"value":"<token>"}'
  ```

  Экспортируйте cookies из своего браузера (где вы уже вошли) любым расширением
  для экспорта cookies (JSON) или в формате Netscape `cookies.txt`.
  Импортируются только cookies доменов этого канала; значения не выводятся.
- **Режим 3** — больше ничего не нужно; новые модели: `./manage.sh add-model`.

## Использование API

```bash
curl https://ваш-домен/v1/chat/completions \
  -H "Authorization: Bearer sk-sf-..." \
  -H "Content-Type: application/json" \
  -d '{"model": "my-model-1", "messages": [{"role": "user", "content": "Привет!"}]}'
```

```python
from openai import OpenAI
client = OpenAI(base_url="https://ваш-домен/v1", api_key="sk-sf-...")
print(client.chat.completions.create(model="my-model-1",
      messages=[{"role": "user", "content": "Привет!"}]).choices[0].message.content)
```

Пользователи создают ключи в консоли (**Ключи**); на странице **Документация**
примеры показаны с вашим доменом и вашими моделями.

## Обслуживание

```bash
./manage.sh status            # контейнеры и состояние
./manage.sh logs api          # логи (api, cluster, db, caddy, ollama)
./manage.sh add-model --id my-fast --provider local --upstream qwen3:8b --price-in 0 --price-out 0
./manage.sh list-models
./manage.sh backup-full       # зашифровано: БД + .env + сессии Chrome + TLS
./manage.sh update            # git pull + пересборка + перезапуск, данные сохраняются
./manage.sh help
```

Прокси для экземпляров Chrome (опционально): см. `backend/cluster/proxies.txt.example`, затем
`docker compose cp proxies.txt cluster:/data/proxies.txt && ./manage.sh restart cluster`.

Остальное (цены, пользователи, лимиты, вход через Google/Telegram, reCAPTCHA,
резервные модели, быстрый путь для простых сообщений) настраивается в админ-консоли.

### Основные параметры `.env`

| Переменная | Назначение |
|---|---|
| `SF_BRAND_NAME`, `SF_ASSISTANT_NAME` | имя платформы / как представляется ассистент |
| `SF_SITE_URL`, `SF_API_URL` | публичные адреса (ссылки, документация, проверка капчи) |
| `SF_DEFAULT_LANG` | `uz`, `ru` или `en` |
| `COMPOSE_PROFILES` | `cluster`, `ollama`, `caddy` — какие дополнительные сервисы запускать |
| `SF_CHROME_CHANNELS` | например `gemini,qwen` — по одному Chrome на канал, по порядку (экземпляр 0, 1, ...) |
| `SF_UPSTREAM_URL` | адрес Ollama (`http://ollama:11434` для встроенного контейнера) |
| `API_BIND`, `API_PORT` | где API публикуется на хосте (по умолчанию `127.0.0.1:8310`) |
| `DB_*_PASSWORD`, `CLUSTER_API_KEY`, `SF_VNC_PASSWORD` | сгенерированные секреты |

Ключи upstream API, OAuth-секреты и подобное хранятся в настройках БД (в
админ-консоли только для записи), а не в `.env`.

### За собственным reverse proxy

Выберите в установщике «за моим reverse proxy» и проксируйте на
`http://127.0.0.1:<API_PORT>`. Пример для nginx — в [README.md](README.md#behind-your-own-reverse-proxy).

## Повторная настройка и резервные копии

Повторный запуск `./install.sh` на установленном сервере — это перенастройка: текущие значения
идут по умолчанию, и он никогда молча не меняет режим оплаты, политику регистрации, пароль
администратора, сохранённые ключи провайдеров и цены моделей. Перевод платного сервиса в
бесплатный режим требует ввести `FREE`; новый пароль админа — `./install.sh --reset-admin-password`.

```bash
./manage.sh backup-full            # backups/gateway-full-<дата>.tar.enc (+ .sha256)
./manage.sh verify-backup FILE     # расшифровка + контрольные суммы + проверка дампа, ничего не меняет
./manage.sh restore-full FILE      # с подтверждением заменяет БД и тома
```

Полная копия содержит БД, `.env`, `Caddyfile`, профили Chrome (сессии провайдеров) и
сертификаты Caddy; `--with-ollama` добавляет локальные модели. Шифрование AES-256 (PBKDF2),
пароль запрашивается или берётся из `BACKUP_PASSPHRASE`. Храните копии и пароль **вне
сервера**; на новом сервере: `./manage.sh extract-env FILE`, проверьте `.env`, затем
`docker compose up -d db && ./manage.sh restore-full FILE`.

Обновление с версии без фиксированной подсети Docker: `./manage.sh backup-full`, затем
`docker compose down && docker compose up -d` (без `-v`, данные сохраняются).

## Безопасность

- **Сеть:** наружу публикуется только порт API (на `127.0.0.1`, если HTTPS не через Caddy) и,
  с Caddy, порты 80/443. PostgreSQL, API кластера и VNC — только во внутренней сети Docker.
  Порты DevTools Chrome слушают `127.0.0.1` внутри контейнера кластера.
- **IP клиентов:** `X-Forwarded-For` принимается только от двух точных адресов: proxy на хосте
  (шлюз сети `172.30.240.1`) и встроенный Caddy (`172.30.240.10`). Другие контейнеры и прямые
  клиенты подменить его не могут. Ваш proxy должен *заменять* заголовок (`$remote_addr` в nginx).
- **Лимиты биллинга** (месячный лимит ключа, бесплатная дневная квота, параллельные запросы
  ключа) учитывают ещё идущие запросы атомарно в БД — параллельные запросы и несколько
  процессов API их не превысят. Резервы упавшего процесса освобождаются примерно за 75 с.
  Бесплатная дневная квота строгая и общая для всех ключей пользователя: запрос принимается,
  только если его худший случай (оценка prompt + `max_tokens`) помещается в остаток; `max_tokens`
  молча не меняется. Сброс в 00:00 по Ташкенту (UTC+5). Ошибки upstream и таймауты не
  оплачиваются; оборванный stream оплачивается за уже доставленные токены.
  `./manage.sh check-integrity` проверяет баланс = журнал, held = резервы.
- **Размер запроса** ограничен и для chunked-загрузок.
- **URL вложений** загружаются только с публичных адресов: имя резолвится один раз,
  внутренние/metadata/CGNAT-адреса отклоняются, редиректы не выполняются.
- **Аккаунты:** при входе через Google на email, где уже есть аккаунт с паролем (саморегистрация),
  пароль и все сессии этого аккаунта сбрасываются (защита от «пред-регистрации» чужого адреса).
- **Контейнеры** работают без лишних capabilities (`cap_drop: ALL`, `no-new-privileges`),
  у контейнера API файловая система только для чтения.
- **Песочница Chrome (fail closed):** Chrome обязан работать в песочнице (`SF_CHROME_SANDBOX=1`).
  Ей нужны непривилегированные user namespaces (Ubuntu 24.04 по умолчанию запрещает их через
  AppArmor). Установщик это проверяет и предлагает: разрешить их на хосте или явно отказаться
  (`SF_CHROME_SANDBOX=0`). Иначе Chrome не запускается. Изоляция сайтов включена по умолчанию.
  Профили Chrome содержат сессии: берегите том `cluster-data` и копии.
- **Общие аккаунты провайдеров:** запросы всех клиентов проходят через одни и те же аккаунты.
- У роли приложения в БД нет DELETE для финансовых таблиц; журнал операций только дописывается.
- Тексты запросов и ответов шлюз не сохраняет — только число токенов и метаданные.
